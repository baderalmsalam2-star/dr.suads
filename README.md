# منصة التدريس

منصة تدريس **مقرر الولاية والوكالة والوصاية** — د. سعاد المطوع.

صفحات ثابتة (HTML/CSS/JS) بلا أي اعتماديات ولا خطوة بناء. تُفتح مباشرةً من
القرص بالضغط على `index.html`، أو تُنشر كما هي على أي استضافة ثابتة.

```bash
# أو عبر خادم محلي بسيط
python3 -m http.server 8000    # ثم http://localhost:8000
```

## ما الذي تفعله

| الصفحة | الغرض |
|---|---|
| `index.html` | المقرر، اختيار الشعبة، **لوحة شرف اليوم**، بطاقات الحصص |
| `register.html` | **باركود التسجيل** — يُعرض على البروجكتر أول حصة |
| `join.html` | صفحة تسجيل الطالبة التي يفتحها الباركود |
| `students.html` | كشف الطالبات: استقبال التسجيل، لصق الأسماء، نسخة احتياطية |
| `attendance.html` | **الحضور والغياب** + جدول التواريخ + تقرير الحرمان + تصدير CSV |
| `student.html` | صفحة الطالبة: نقاطها وترتيبها وسجل تفاعلها وتسليماتها وملفاتها |
| `worksheets.html` | أوراق العمل والواجبات + مصفوفة حالة التسليم + استلام التسليمات |
| `worksheet.html` | حل الورقة داخل المتصفح — بلا ورق |
| `honors.html` | لوحة الشرف: اليوم · الشهر · الفصل كاملًا |
| `sessions/*.html` | عرض الحصة، وبداخله لوحة رصد التفاعل |

## البنية

```
data/course.js          ← الشعب والحصص وأنواع التفاعل ونقاطها
data/worksheets.js      ← أوراق العمل والواجبات
assets/store.js         طبقة البيانات (كل قراءة وكتابة تمر منها)
assets/qr.js            مولّد رمز QR — مكتوب هنا بلا اعتمادية خارجية
assets/ui.js            ترويسة وتنقل ومساعدات مشتركة
assets/tokens.css       ألوان الجامعة والخطوط
assets/app.css          أنماط صفحات المنصة
assets/deck.css/.js     عرض الحصة
assets/participate.js   لوحة رصد التفاعل داخل العرض
```

## تسجيل الطالبات بالباركود

باركود واحد يُعرض في أول حصة: الطالبة تمسحه → تكتب اسمها ورقمها
الجامعي → يظهر لها رمز تعرضه على الدكتورة فتدخل الكشف.

الباركود مولَّد داخل المنصة (`assets/qr.js`) بلا أي مكتبة خارجية، فيعمل
بلا إنترنت. والاستقبال بثلاث طرق: **مسح بالكاميرا** عبر `BarcodeDetector`
حيث يدعمه المتصفح، أو **لصق الرموز** نصًّا، أو **استلام ملفات** التسجيل.
الطالبة المكرَّرة تُكتشف برقمها الجامعي.

> الباركود يحمل عنوان المنصة على الشبكة، فيلزم تشغيلها عبر خادم محلي
> لا من `file://` — الخطوات في «دليل التشغيل».

## الحضور والغياب

جدول تواريخ يُولَّد مرة واحدة (أول محاضرة + أيام الأسبوع)، ثم في كل حصة:
**الكل حاضرات** ثم تعليم الغائبات. الحالات أربع: حاضرة · متأخرة · بعذر · غائبة.

التقرير يحسب نسبة غياب كل طالبة ويعلّم من قاربت الحد ومن تجاوزته.
**«بعذر» لا تُحتسب غيابًا ولا تدخل في المقام.** الحدود في `data/course.js`
تحت `attendance` (افتراضيًا حرمان ٢٥٪ وتنبيه ١٥٪) — عدّليها بحسب لائحة
الكلية. والتصدير CSV بترميز يفتح العربية في Excel صحيحة.

## رصد التفاعل ولوحة الشرف

أثناء الشرح، افتحي لوحة الرصد داخل العرض بمفتاح **م** (أو زر «رصد»)،
اضغطي اسم الطالبة ثم نوع التفاعل. تُحفظ النقطة فورًا وتظهر أمام اسمها،
وزر **تراجع** يلغي آخر رصد.

النقاط الافتراضية — تُعدَّل في `data/course.js`:

| النوع | النقاط |
|---|---|
| قراءة | ٢ |
| إجابة صحيحة | ٣ |
| سؤال | ٢ |
| مشاركة ومناقشة | ١ |
| تسليم ورقة عمل | ٣ (يُرصد تلقائيًا عند التسليم، مرة واحدة لكل ورقة) |

لوحة الشرف تعرض **أول ثلاث طالبات** في المدى المختار — اليوم أو الشهر
(للـ midterm ونهاية الشهر) أو الفصل كاملًا — ثم الترتيب الكامل مفصَّلًا
بأنواع التفاعل. التعادل على المركز الثالث يُذكر صراحةً لا يُخفى.

> هذه **نقاط تفاعل صفّي، لا درجات أكاديمية**. أوراق العمل نفسها بلا درجات:
> بعد التسليم تظهر الإجابة الصحيحة وتعليقها، ويُعلَّم اختيار الطالبة الخاطئ
> لتعرف أين وقع اللبس.

## أوراق العمل — بلا ورق

الطالبة تحل داخل المتصفح: اختيار من متعدد، إجابة قصيرة، إجابة مطوّلة،
ورفع ملف (صورة أو PDF، حتى ٦ م.ب). المسودة تُحفظ تلقائيًا، وبعد التسليم
تُقفل الحقول وتظهر الأجوبة.

**كيف يصل التسليم للدكتورة؟** الوضع الحالي بلا خادم، وتخزين كل متصفح
مستقل عن غيره، فالدورة هكذا:

1. الطالبة تضغط **«تنزيل ملف التسليم»** → ينزل ملف باسم مثل
   `tasleem-sec1-no3-w1-2026-09-05.json` (اسمها العربي داخل الملف لا في اسمه،
   لأن المتصفحات تُسقط الأسماء غير اللاتينية من روابط التنزيل).
2. ترسله بأي وسيلة (بريد، تيمز، واتساب).
3. الدكتورة تفتح **أوراق العمل → «استلام ملف تسليم»** وتختار الملفات
   (عدة ملفات دفعة واحدة). يُطابَق التسليم على الطالبة بالمعرّف ثم بالاسم
   داخل شعبتها، ويُحدَّث لا يُكرَّر، وتُرصد نقطة التسليم تلقائيًا.

## إضافة حصة جديدة

1. انسخي `sessions/01-tareef-al-wilaya.html` باسم جديد.
2. غيّري `<title>` و `data-session` في وسم `<body>` إلى رقم الحصة.
3. استبدلي أقسام `<section class="slide">` بمحتوى الحصة.
4. أضيفي الحصة إلى `sessions` في `data/course.js` واجعلي `status: "ready"`.

### وسوم الشرائح

| الوسم | أثره |
|---|---|
| `data-tab="…"` | نص اللسان الأصفر أعلى الإطار |
| `data-src="…"` | المصدر أو رقم الصفحة في الشريط العلوي |
| `data-reader` | شريحة قراءة — تُسنَد إلى طالبة تلقائيًا (بالاسم إن وُجد الكشف) |
| `data-timer="30"` | مؤقت بعدد الثواني عند ظهور الشريحة |
| `data-q` | شريحة سؤال — مسافة تُظهر الإجابة الصحيحة |

## الشعب وتوزيع القارئات

الشعب في `data/course.js`، وعدد `roster` فيها احتياطي يُستعمل قبل إدخال
الكشف فقط — متى وُجد كشف بالأسماء صار هو المرجع في عدد القارئات.

الكشف يُلصق من صفحة «الطالبات» سطرًا لكل طالبة، إما الاسم وحده أو
`الرقم الجامعي  الاسم`. وترتيب الأسماء هو نفسه ترتيب القارئات في الحصص.
ويُعدَّل بعد ذلك بالإضافة والتعديل والحذف داخل الجدول مباشرة. عند إعادة
اللصق تُطابَق الطالبة بالرقم الجامعي ثم بالاسم، فلا ينفصل سجل تفاعلها عنها.

القارئات تُوزَّع دائريًا: تبدأ الحصة من `startAt` وتلتف عند تجاوز عدد
المسجّلات، فتنتقل الدورة بين الحصص تلقائيًا. الرابط يقبل
`?section=2&roster=20&startAt=6` لتجاوز الإعداد دون تعديل أي ملف.

## أثناء الحصة

| المفتاح | الأثر |
|---|---|
| `←` / `→` | الشريحة التالية / السابقة |
| `مسافة` | إظهار الجواب |
| `ر` | إعادة تشغيل المؤقت |
| `م` | فتح وإغلاق لوحة رصد التفاعل |
| `Home` / `End` | أول / آخر شريحة |

النقر ينتقل للتالي، والسحب بالإصبع يعمل على الأجهزة اللمسية.
**الطباعة** تُصدِّر الحصة كاملةً (كل شريحة في صفحة، والأجوبة ظاهرة).

## أين تُحفظ البيانات

على **جهاز المتصفح نفسه**: السجلات في `localStorage` والملفات المرفوعة في
`IndexedDB`. لا يُرسَل شيء إلى أي خادم.

يعني ذلك أمرين:

- **خذي نسخة احتياطية بانتظام** — صفحة الطالبات → «نسخة احتياطية»، وتُستعاد
  من «استعادة» (تدمج ولا تمسح). مسح بيانات المتصفح يمسح كل شيء.
- **لا يوجد تزامن بين الأجهزة** — ما يُرصد على جهاز الدكتورة يبقى عليه،
  وتسليم الطالبة يصل بملف التسليم كما سبق.

### تركيب خادم لاحقًا

كل قراءة وكتابة تمر من `assets/store.js`، وواجهته غير متزامنة عمدًا
(كل دالة تُرجع `Promise`) حتى يُستبدل التخزين المحلي بخادم دون تغيير سطر
في بقية الملفات. اكتبي كائنًا بنفس الدوال — `students` و `saveStudent` و
`events` و `addEvent` و `submissions` و `saveSubmission` و `putFile`
و `getFile` … — ثم عيّنيه قبل تحميل `store.js`:

```html
<script>window.TP_ADAPTER = MyServerAdapter;</script>
<script src="assets/store.js"></script>
```

عندها يرفع كل جهاز إلى الخادم مباشرة، ويسقط ملف التسليم من الدورة.
